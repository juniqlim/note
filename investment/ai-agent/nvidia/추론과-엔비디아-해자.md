# 추론과 엔비디아 해자 — CUDA는 얕아지고 HBM은 남는다

작성: 2026-11-17 / 계기: Wired, "Nvidia Was Already in Trouble Before the Jensen Huang Mess" ([GeekNews 요약](https://news.hada.io/topic?id=37301))
연결: [엔비디아-실적분석.md](엔비디아-실적분석.md) ② 가격결정권 · [메모리-수급.md](../hynix/메모리-수급.md) · [추론인프라-병목.md](../hynix/추론인프라-병목.md)

> **결론 먼저**: 추론 비중이 커지면 엔비디아가 불필요해지는 것이 아니라 **엔비디아만 필요한 것이 아니게 된다.** 소프트웨어 해자(CUDA)는 학습에서 깊고 추론에서 얕다. 반면 추론 속도는 메모리 대역폭에 묶여 있어, 칩이 엔비디아에서 자체 ASIC으로 바뀌어도 HBM은 따라간다. 볼 지표는 엔비디아는 **총마진**, 메모리는 **HBM 프리미엄**이다.

> ⚠ 기사 속 수치와 사건(젠슨 황 사퇴, AMD 점유율 7~10%, 중국 매출 비중 8%)은 요약본 기준이며 원문·공시로 검증하지 않았다. 대역폭·토큰 속도는 어림값이다.

---

## 1. 추론이란

**추론(inference) = 학습된 모델을 실행하는 것 = 서빙.** 새로 생긴 것이 아니라 ChatGPT 첫날부터 있었다. 개인이 Ollama로 모델을 돌리는 것도 같은 추론이고, 데이터센터와의 차이는 규모뿐이다.

- 번역어 주의: o1류의 "길게 생각하는" 기능은 reasoning이다. 기사의 추론은 inference다.
- 바뀐 것은 비중이다. 초기에는 컴퓨팅 대부분이 학습에 쓰였고, 지금은 사용자 증가 + 에이전트·reasoning 모델의 토큰 소모(요청당 수십~수백 배)로 추론 쪽이 급증했다.
- 기사의 논리: 컴퓨팅 수요의 무게중심이 엔비디아 우위가 작은 쪽으로 옮겨간다.

## 2. CUDA 해자 — 학습에서 깊고 추론에서 얕다

| | 학습 | 추론 |
|---|---|---|
| 필요한 연산 | 새 연산·디버깅·분산 학습 도구 전부 | 적고 고정됨 |
| 전환 비용 | 생태계 전체에 묶임 | 한 번 포팅하면 됨 |
| 전환 주체 | 연구자 전원 | 서비스 제공자 한 곳 (사용자는 API로 토큰만 받음) |

**CUDA 없이 돌아가는 사례**: 구글 TPU(Gemini), 아마존 Trainium(Claude), 애플 실리콘·퀄컴 NPU(온디바이스), AMD ROCm. 맥북에서 CUDA 없이 로컬 모델이 도는 것이 직접적인 예다.

**그래도 남는 이유**
- 새 모델·새 기법은 CUDA에서 먼저 나오고 가장 잘 최적화된다.
- 포팅은 가능하지만 성능을 끝까지 짜내려면 인력이 필요하다 → 대형 업체만 쉽게 넘어간다.
- AI 연산은 SHA-256 같은 고정 함수가 아니어서, 채굴처럼 ASIC이 100배 이기는 구도가 아니다.

**기사가 꼽은 추가 위협**: AI가 코드를 다른 하드웨어로 옮겨주면 포팅 비용 자체가 내려간다(스타트업 Wafer가 AMD로 옮겨 저가 서빙).

## 3. 사고실험 — 추론의 시대이고 새 모델이 더디게 나온다면

**무너지는 것**
- 범용성의 값어치. 모델이 고정되면 전용 칩의 투자 회수가 쉬워진다.
- 극단적으로는 Taalas(AMD 인수)처럼 가중치를 실리콘에 새기는 방식까지 성립한다.
- 결과는 소멸이 아니라 **범용품화**다. 칩은 팔리지만 총마진 70%대를 지킬 근거가 약해진다.

**남는 것**

| 해자 | 내용 |
|---|---|
| 공급 | TSMC 첨단 공정·패키징과 HBM 물량 선점 |
| 시스템 | NVLink·네트워킹·랙 단위 완제품 |
| 구매 가능성 | TPU·Trainium은 자사 클라우드 전용. 자체 칩이 없는 클라우드·국가·기업이 살 수 있는 것은 엔비디아와 AMD 정도 |
| 성능 | 하드웨어 성능·전력 효율 선두권 |

**가정 자체의 문제**: 지금 시장은 반대로 움직인다(몇 달 간격의 새 모델, 학습 투자 증가). 모델 발전이 느려지면 엔비디아 해자보다 **AI 투자 전체 규모**가 먼저 문제가 된다.

## 4. 추론 칩과 메모리 — 병목은 대역폭

LLM 추론은 토큰 하나를 만들 때마다 가중치 전체를 메모리에서 읽는다.

**토큰 속도 상한 ≈ 메모리 대역폭 ÷ 모델 크기**

| 메모리 구성 | 대역폭 | 40GB 모델(70B, 4비트) 상한 | HBM(H200) 대비 |
|---|---|---|---|
| 데스크톱 DDR5 (2채널) | ~90GB/s | 초당 ~2토큰 | ~1/50 |
| 서버 DDR5 (8~12채널) | ~300~600GB/s | 초당 8~15토큰 | ~1/8~1/16 |
| 애플 M Max·Ultra (LPDDR) | ~400~800GB/s | 초당 10~20토큰 | ~1/6~1/12 |
| 엔비디아 H200 (HBM3E) | ~4,800GB/s | 초당 100토큰 이상 | 1 |
| 엔비디아 B200 | ~8,000GB/s | — | 1.7배 |

- 사용자 한 명 기준. 서버 DDR 대비 **칩 하나끼리 ~10배**, GPU 8개가 들어가는 시스템 단위로는 100배에 가깝다.
- **차이의 원인은 선의 수**다. 대역폭 = 데이터 선 개수 × 선당 속도. DDR은 메인보드 배선·소켓을 거쳐 채널당 64개, HBM은 칩 옆에 붙여 TSV로 스택당 1,024개(HBM4는 2,048개), 이를 칩당 6~8스택.
- DDR 규격이 올라가도 선 수가 구조적으로 제한돼 격차는 좁혀지기 어렵다.

**HBM 없이 하는 방식**

| 방식 | 예 | 장점 | 한계 |
|---|---|---|---|
| 칩 내부 SRAM | Groq, Cerebras | 가장 빠름 | 용량이 작아 큰 모델에 칩이 많이 필요 |
| LPDDR 다채널 | 퀄컴 AI200, 인텔 Crescent Island, 애플 실리콘 | 싸고 용량 크고 저전력 | 대역폭이 낮아 느림 |
| GDDR | 엔비디아 저가형 추론 카드 | 저렴 | 용량·대역폭 모두 중간 |
| 가중치 각인 | Taalas | 메모리 읽기가 없음 | 모델을 바꿀 수 없음 |

TPU·Trainium·Maia 같은 자체 칩은 엔비디아를 벗어났을 뿐 HBM은 그대로 쓴다.

## 5. 대역폭 문제가 풀리면 — 흔들리는 것은 HBM 프리미엄

메모리 수요 전체가 아니다. 어떤 방법이든 가중치를 담을 메모리는 필요하고 공급자는 같은 세 곳이다.

| 방법 | 내용 | 상태 |
|---|---|---|
| 모델 쪽 절감 | 양자화, 증류, MoE | 진행 중. 가장 빠르게 효과 |
| LPDDR 다채널 | 싼 메모리를 칩 가까이 많이 연결 | 퀄컴·인텔 추론 칩이 채택 |
| HBF | 낸드를 HBM처럼 적층 ([hynix.md §19](../hynix/hynix.md)) | 개발 중 |
| 로직 위 직접 적층 | D램을 연산 칩 위에 하이브리드 본딩 | 초기 단계 |
| PIM | 메모리에서 직접 계산 | 양산 사례 드묾 |

**흔들림의 크기**
- **SK하이닉스**: HBM 이익 의존도가 가장 높아 프리미엄 축소에 가장 민감.
- **HBM 전용 장비**(TC 본더 등): 적층 공정이 바뀌면 수요 자체가 사라질 수 있어 메모리 업체보다 위험이 크다.
- **삼성·마이크론**: 범용 D램·LPDDR 비중이 커서 덜 흔들린다.

**반대 방향의 힘**: 추론 단가가 내려가면 사용량이 늘어 메모리 총수요는 커질 수 있다. HBM 자체도 세대마다 대역폭을 올리며 대체재보다 먼저 달아난다.

단기에 가능성이 높은 것은 기술 교체보다 **모델 효율화로 토큰당 필요 메모리가 줄어드는 쪽**이고, 이는 HBM 가격 협상에서 먼저 나타난다.

## 6. 관찰 지표

| 대상 | 지표 | 의미 |
|---|---|---|
| 엔비디아 | 총마진 방향 | 해자가 얕아지면 점유율보다 먼저 드러난다 |
| 엔비디아 | 추론 시장 ASIC 점유율 | 실적분석 ⓑ와 동일 |
| 메모리 | HBM과 범용 D램의 마진 격차 | 프리미엄 축소 여부 |
| 메모리 | LPDDR 기반 추론 칩의 채택 규모 | 대체 경로의 실현 정도 |
| 공통 | 새 모델 출시 간격·학습 투자 | §3 가정이 현실이 되는지 |
